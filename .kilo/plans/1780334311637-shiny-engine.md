## Fix 1: Validate `sheetName` for path traversal — `src/schematic.ts:74,171`

**File**: `@typecad/typecad/src/schematic.ts`

Add a validation function that rejects `sheetName` values containing path traversal characters (`..`, `/`, `\`, `\0`) or shell metacharacters. Call it in the `Schematic` constructor.

```ts
function validateSheetName(name: string): void {
    if (!name || name.includes('..') || name.includes('/') || name.includes('\\') || name.includes('\0')) {
        throw new TypeCadError(
            `Invalid sheet name '${name}': must not contain path traversal characters (.., /, \\)`
        );
    }
    if (name.trim() !== name) {
        throw new TypeCadError(
            `Invalid sheet name '${name}': must not have leading/trailing whitespace`
        );
    }
}
```

- Add call `validateSheetName(sheetName)` at top of constructor (line 75)
- The file write at line 171 will now be safe

## Fix 7: Add cleanup on partial failure — `src/cli/create-typecad/create_project.ts`

**File**: `@typecad/typecad/src/cli/create-typecad/create_project.ts`

Add a cleanup mechanism that removes the partially-created project directory on failure.

1. Track the project root path at the start:
```ts
const projectRoot = path.join(process.cwd(), answers.name);
let createdDirs = false;
```

2. Add a cleanup helper function:
```ts
function cleanup() {
    if (createdDirs && fs.existsSync(projectRoot)) {
        try {
            fs.rmSync(projectRoot, { recursive: true, force: true });
            logger.log(chalk.yellow("!"), "Cleaned up partial project directory");
        } catch (cleanupErr) {
            logger.error(`Failed to clean up ${projectRoot}. Remove it manually.`, cleanupErr);
        }
    }
}
```

3. Set `createdDirs = true` after the first `mkdirSync` succeeds (around line 44).

4. Wrap each error-handling `return` in `create_project()` (lines 71, 85, 99, 168, 185, 221, 260, 276, 317, 440, 461) with `cleanup()` before the return, or better: restructure to use a single try/catch that calls `cleanup()` in the catch block and re-throws.

The cleaner approach: wrap the body of `create_project` in a try/catch:

```ts
export function create_project(answers: ProjectAnswers) {
    answers.name = sanitizeProjectName(answers.name);
    const projectRoot = path.resolve(answers.name);
    let createdDirs = false;

    function cleanup() {
        if (createdDirs && fs.existsSync(projectRoot)) {
            try {
                fs.rmSync(projectRoot, { recursive: true, force: true });
                logger.log(chalk.yellow("!"), "Cleaned up partial project:", projectRoot);
            } catch (e) {
                logger.error(`Failed to clean up ${projectRoot}. Remove it manually.`);
            }
        }
    }

    try {
        // ... existing function body (all the mkdir, writeFileSync, etc.)
        // Replace early returns with throwing an error or use a result flag
        // Set createdDirs = true after first directory creation succeeds
    } catch (err) {
        cleanup();
        logger.error(chalk.red(`Project creation failed: ${(err as Error).message}`));
    }
}
```

However, the current code uses early `return` on error (not throw). The minimal-impact approach: add `cleanup()` before each early return. This is verbose but avoids restructuring. 

**Chosen approach (per user preference)**: Restructure `create_project()` to wrap the entire body in a try/catch. Convert all early `return` statements to `throw new Error(...)` so the catch block handles cleanup centrally.

The restructured function:

```ts
export function create_project(answers: ProjectAnswers) {
    answers.name = sanitizeProjectName(answers.name);
    const projectRoot = path.resolve(answers.name);
    let createdDirs = false;

    try {
        // Directory creation (existing lines 42-55)
        let dir = `./${answers.name}/hw/build/lib/footprints`;
        if (!fs.existsSync(dir)) {
            fs.mkdirSync(dir, { recursive: true });
        }
        createdDirs = true;  // Mark after first successful dir creation
        
        // ... all existing file operations, but replace:
        //   return;  →  throw new Error('description of what failed');
        // ... rest of function unchanged except throw instead of return
    } catch (err) {
        if (createdDirs && fs.existsSync(projectRoot)) {
            try {
                fs.rmSync(projectRoot, { recursive: true, force: true });
                logger.log(chalk.yellow("!"), "Cleaned up partial project:", projectRoot);
            } catch (cleanupErr) {
                logger.error(`Failed to clean up ${projectRoot}. Remove it manually.`);
            }
        }
        logger.error(chalk.red(`Project creation failed: ${(err as Error).message}`));
    }
}
```

Each existing `return` on error becomes a `throw new Error(...)` with the same error message that was previously logged. This keeps the same user-facing behavior but adds automatic cleanup.
