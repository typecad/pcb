# Fix: lib_symbol_mismatch ERC warnings for power symbols (GND, VCC)

## Root Cause

The s-expression parser (`src/sexpr/parse.ts`) does **not** unescape string literals during parsing. When it reads `"Power symbol creates a global label with name \"GND\" , ground"`, the returned JavaScript string retains the literal backslash-quote characters: `...name \"GND\"...`.

When the serializer (`src/sexpr/serialize.ts`) writes this string back out, `escapeSexprString()` (in `src/sexpr/escape.ts`) escapes `\` → `\\` and `"` → `\"`, producing: `...name \\\"GND\\\"...` — double-escaped.

KiCad's ERC compares the embedded `lib_symbols` entry against the actual library file and sees `\\\"` vs `\"`, triggering `lib_symbol_mismatch` warnings for any symbol whose Description (or any property) contains escaped quotes. Power symbols (GND, VCC) always have Description strings like `"Power symbol creates a global label with name \"GND\""`.

## Fix

**File: `src/sexpr/parse.ts` — `readString()` function (lines 34–49)**

Change the parser to unescape string content. Currently it returns the raw substring between quotes. Instead, it should process escape sequences:
- `\"` → `"`
- `\\` → `\`

This is the standard approach — the parser stores the *semantic* content, the serializer re-escapes on output. This ensures a correct round-trip: parse → serialize produces identical output.

**Specific change in `readString()`:**

Replace the current implementation that returns `input.substring(start, pos)` with one that builds the string character-by-character, processing `\` escape sequences:
- When `\` is encountered, skip it and append the next character literally (handling `\"` and `\\`)
- Otherwise append the character as-is
