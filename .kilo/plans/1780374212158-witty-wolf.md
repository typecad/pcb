# Plan: Use `reportError()` in Schematic Renderer for Variable Name Error Messages

## Problem
Schematic error messages show only auto-numbered reference designators (e.g., `U1`) instead of the user's variable name (e.g., `bt1`). The `Component.sourceInfo.variable` is already populated via acorn AST parsing, but the schematic renderer ignores it.

## Solution
Wire up the existing `reportError()` from `src/utils/error_reporter.ts` into the schematic renderer for user-facing errors. Also add a lightweight `displayName()` helper for warning messages that don't need full source context.

## Files to Modify

### 1. `src/renderers/kicad_schematic_renderer.ts`

- **Add `sourceInfo?` to `RenderableSymbol` interface** so the type system knows about it
- **Import `reportError`** from `../utils/error_reporter.js`
- **Add a `displayName()` helper** that produces `"bt1 (U1)"` or just `"U1"` if variable is unavailable
- **Line 41**: Replace `logError(...)` with `reportError()` for "has no symbol defined"
- **Line 121**: Replace `logError(...)` with `reportError()` for "has no symbol"
- **Lines 47, 50, 54, 58, 64, 75**: Use `displayName()` in warning messages (coordinates, missing sch data, symbol not found)
- **Lines 125, 129**: Use `displayName()` in `getAbsolutePinCoordinates` error messages
- **Lines 175, 231, 235**: Use `displayName()` in `net()` warnings for pin coordinate resolution

### 2. `src/renderers/schematic_visualizer.ts`

- **Import `reportError`** from `../utils/error_reporter.js`
- **Line 28**: Use `displayName()` in "Skipping symbol instance" warning
- **Line 31**: Replace `logWarning(...)` with `reportError()` for "missing a symbol" (this is the key user-facing case)

### 3. `src/renderers/schematic_visualizer_types.ts`

- **Export a `displayName()` helper** that accepts a `RenderableSymbol` (with optional `sourceInfo`) and returns `"variableName (reference)"` or just `"reference"`

### 4. `src/pcb/pcb_board_creation.ts`

- **Import and call `awaitPendingInspections()`** before `schematic(pcb.schematic!)` on line 140 to ensure all `sourceInfo.variable` values are populated before schematic generation runs. This is critical since `inspectSource` is async.

## Detailed Changes

### `schematic_visualizer_types.ts` — Add `displayName()`

Add a `displayName(component)` function:
```typescript
export function displayName(component: { reference?: string; sourceInfo?: { variable?: string } }): string {
    const ref = component.reference || 'UNKNOWN';
    const variable = component.sourceInfo?.variable;
    return variable ? `${variable} (${ref})` : ref;
}
```

Also add `sourceInfo?` to be importable — but since `RenderableSymbol` is in `kicad_schematic_renderer.ts`, we'll extend it there.

### `kicad_schematic_renderer.ts` — Extend interface + use helpers

Extend `RenderableSymbol`:
```typescript
interface RenderableSymbol {
    symbol?: string;
    reference: string;
    value: string;
    footprint?: string;
    sch: { x: number; y: number; rotation?: number };
    sourceInfo?: { file?: string; line?: number; variable?: string };
}
```

Replace error calls (the two `logError` calls that correspond to "has no symbol"):
- Line 41: `logError(...)` → `reportError('Component has no symbol defined.', component)`
- Line 121: `logError(...)` → `reportError('Component has no symbol.', component)`

Replace all `component.reference || component.symbol` patterns in warnings with `displayName(component)`:
- Lines 47, 50, 54, 58, 64, 75, 113, 125, 129

In `net()` method, update pin owner references:
- Line 175: Use `displayName(pinDef.owner)` for the "Could not get absolute coordinates" warning
- Lines 231, 235: Same pattern

### `schematic_visualizer.ts` — Use `reportError` for missing symbol

Line 31 — the key error the user sees:
