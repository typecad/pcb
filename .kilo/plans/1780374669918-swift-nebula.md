# Plan: Use `reportError()`/`displayName()` in All Locations Where Component Owner Data Is Available

## Problem
Error and warning messages across the codebase show only auto-numbered reference designators (e.g., `U1`) instead of the user's variable name (e.g., `bt1`). The `Component.sourceInfo.variable` is populated via acorn AST parsing and awaited before schematic generation, but many modules don't use it.

## Approach
- Use `reportError()` for actual errors (fatal failures) — shows full source context with variable name, file, and code snippet
- Use `displayName()` for warnings (non-fatal) — shows `"variableName (reference)"` or just `"reference"` if variable is unavailable

## Prerequisite: Move `displayName()` to `error_reporter.ts`

`displayName()` is currently in `schematic_visualizer_types.ts`, which imports from `component.ts`. This creates a circular dependency when `component.ts` tries to import `displayName`. Moving it to `error_reporter.ts` (which has no `component.ts` dependency) solves this.

### `src/utils/error_reporter.ts`
- Add the `displayName()` function (identical implementation)
- No new imports needed — the function is self-contained

### `src/renderers/schematic_visualizer_types.ts`
- Remove the `displayName()` function definition
- Re-export from `error_reporter.ts`: `export { displayName } from '../utils/error_reporter.js';`
- This preserves backward compatibility for `kicad_schematic_renderer.ts` and `schematic_visualizer.ts`
