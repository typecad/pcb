# Fix: `typecad import` not applying side changes for inline PCB definitions

## Root Cause

In `@typecad/typecad/src/kicad2typecad/rewriter.ts`, the `applyFootprintChanges()` method has three branches for handling PCB property updates:

1. **`pcbAssignment` branch** (lines 495-516): Separate `.pcb = { ... }` assignments — side is partially handled
2. **`inlinePcb` branch** (lines 517-527): `pcb: { ... }` inside constructor call — **NO side handling at all**
3. **No-PCB branch** (lines 528-548): Creates new `.pcb = { ... }` — side IS handled

The user's code uses inline `pcb: { x, y, rotation }` in the constructor (e.g., line 8 of test_0.3.ts). When only the side changes (front → back), the inlinePcb branch pushes replacements for x/y/rotation that produce identical text, and no side replacement is added. This results in `applyReplacements()` detecting no change (`modified === source`), hence "Applied 1 component change(s) to **0** file(s)."

### Secondary bug

In the `pcbAssignment` branch (line 506), side is only handled when `change.newSide === 'back'`. If a component changes from back to front, the existing `side: 'back'` property is never updated or removed.

## Fix

**File: `@typecad/typecad/src/kicad2typecad/rewriter.ts`**

### Change 1: Add side handling to the `inlinePcb` branch (lines 517-527)

After the rotation replacement (line 527), add side handling mirroring the `pcbAssignment` branch pattern:

```typescript
} else if (component.inlinePcb) {
    const props = component.inlinePcb.props;
    if (props['x'] && change.newX !== undefined) {
        replacements.push({ range: props['x'].range, newValue: String(change.newX) });
    }
    if (props['y'] && change.newY !== undefined) {
        replacements.push({ range: props['y'].range, newValue: String(change.newY) });
    }
    if (props['rotation'] && change.newRotation !== undefined) {
        replacements.push({ range: props['rotation'].range, newValue: String(change.newRotation) });
    }
    // --- NEW: side handling ---
    if (change.newSide === 'back') {
        if (props['side']) {
            replacements.push({ range: props['side'].range, newValue: "'back'" });
        } else {
            const insertPos = component.inlinePcb.range.end - 1;
            replacements.push({
                range: { start: insertPos, end: insertPos },
                newValue: `, side: 'back'`,
            });
        }
    } else if (change.newSide === 'front' && props['side']) {
        // Remove side property when changing back → front
        // Need to also remove the preceding comma and whitespace
        // TODO: handle removing side: 'back' from inline pcb
    }
}
```

**Note on `inlinePcb.range`**: The `inlinePcb` has a `range` property (from source_analyzer.ts line 447: `range: props['pcb'].range`). This points to the entire `pcb` property value. We need to use `component.inlinePcb.range.end - 1` as the insertion point (just before the closing `}`), same pattern as `pcbAssignment.objectRange.end - 1`.

### Change 2: Handle back → front in the `pcbAssignment` branch (lines 506-516)

Currently only `change.newSide === 'back'` is handled. Need to also handle the reverse direction to remove/update an existing `side: 'back'` when changing to front.

This is more complex because removing a property from an inline object requires knowing the preceding comma/separator. A simpler approach is to replace the value with `'front'` (even though front is the default), which avoids complex comma handling.
