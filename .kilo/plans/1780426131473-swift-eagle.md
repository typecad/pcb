# Plan: Intuitive Component Placement API

## Goal
Add a fluent, ergonomic placement API to typeCAD that lets users position components relative to each other and to the board workspace, instead of using raw mm coordinates.

## User API Examples

```ts
// Relative placement — below() returns a number for y
let r1 = new Component({ footprint: 'Resistor_SMD:R_0805', pcb: { x: 10, y: 10 } });
let r2 = new Component({ footprint: 'Resistor_SMD:R_0805', pcb: { x: r1.pcb.x, y: below(r1).by(3) } });

// Workspace-relative placement
let u1 = new Component({ footprint: '...', pcb: { x: workspace(pcb).center.x, y: workspace(pcb).center.y } });

// Combine both
let c1 = new Component({ footprint: '...', pcb: { x: workspace(pcb).left + 5, y: workspace(pcb).center.y } });
let c2 = new Component({ footprint: '...', pcb: { x: rightOf(c1).by(2), y: sameAs(c1) } });
```

## Architecture

### 1. New file: `src/placement.ts`

Contains all placement helper functions:

#### `below(component).by(gap)` — Relative Positioning

```ts
// Each function returns a builder with .by() that returns a number
function below(component: Component): PlacementBuilder;
function above(component: Component): PlacementBuilder;
function rightOf(component: Component): PlacementBuilder;
function leftOf(component: Component): PlacementBuilder;
function sameAs(component: Component): number;  // returns the component's current x or y directly — context-dependent, see below
```

**PlacementBuilder interface:**
```ts
interface PlacementBuilder {
  by(gap: number): number;
}
```

Each function reads the component's bounding box to account for physical size:

- `below(r1)` → returns builder whose `.by(gap)` returns `r1.pcb.y + r1BoundingBox.height/2 + gap`
- `above(r1)` → returns builder whose `.by(gap)` returns `r1.pcb.y - r1BoundingBox.height/2 - gap`
- `rightOf(r1)` → returns builder whose `.by(gap)` returns `r1.pcb.x + r1BoundingBox.width/2 + gap`
- `leftOf(r1)` → returns builder whose `.by(gap)` returns `r1.pcb.x - r1BoundingBox.width/2 - gap`

**Default gap:** `.by()` without argument uses a default of 2mm.

**Bounding box resolution:** We need a utility to get a component's footprint bounding box. This can be:
- Cached at component construction time from the footprint file
- Approximated from pad positions in the footprint
- See section 2 below for implementation details

**`sameAs(component)` helper:** Since `below`/`above` return y-values and `leftOf`/`rightOf` return x-values, we also need a way to say "same coordinate as". We'll offer:
```ts
sameAs(component).x  // returns component.pcb.x
sameAs(component).y  // returns component.pcb.y
```
This uses a simple object with getter properties.

#### `workspace(pcb)` — Board-Aware Positioning

```ts
function workspace(pcb: PCB): WorkspaceBounds;
```

**WorkspaceBounds interface:**
```ts
interface WorkspaceBounds {
  readonly center: { x: number; y: number };
  readonly top: number;     // minimum y of all outlines
  readonly bottom: number;  // maximum y of all outlines
  readonly left: number;    // minimum x of all outlines
  readonly right: number;   // maximum x of all outlines
  readonly width: number;
  readonly height: number;
  readonly topLeft: { x: number; y: number };
  readonly topRight: { x: number; y: number };
  readonly bottomLeft: { x: number; y: number };
  readonly bottomRight: { x: number; y: number };
}
```

Derived from `pcb.state.outlines` — scans all outline elements (lines, arcs) to compute the bounding box of the board edge cuts. This is computed lazily on access.

### 2. Footprint Bounding Box Utility

**New file: `src/pcb/footprint_bounds.ts`**

```ts
function getFootprintBounds(footprintName: string): { width: number; height: number } | null;
```

This function:
1. Looks up the footprint `.kicad_mod` file (using the existing footprint resolution logic in `pcb_footprint.ts`)
2. Parses the footprint to extract pad positions and their sizes, plus any courtyard/fab layer outlines
3. Computes the bounding box from all graphical elements and pads
4. Caches the result per footprint name (static Map)

If the footprint can't be resolved, returns `null` and the placement functions fall back to using just the anchor point (no size offset).

**Integration with Component:** Add a lazy `_bounds` cache to Component:
```ts
// In Component class (internal, lazy)
private _bounds?: { width: number; height: number } | null;
get bounds(): { width: number; height: number } | null { ... }
```

### 4. Implementation Steps

1. **Create `src/pcb/footprint_bounds.ts`**
   - Implement `getFootprintBounds(footprintName)` using the footprint file loading logic already in `pcb_footprint.ts`
   - Parse the S-expression to find pad positions, courtyard lines, and compute bounding box
   - Use a static `Map<string, bounds>` for caching

2. **Add `bounds` getter to `Component`** (`src/component.ts`)
   - Lazy property that calls `getFootprintBounds(this.#footprint)` on first access
   - Returns `{ width, height }` or `null` if footprint not resolvable

3. **Add outline bounding box to `PcbInternalState`** (`src/pcb/pcb_state.ts`)
   - Add `getOutlineBounds(): { minX, minY, maxX, maxY }` that scans `this.outlines` and `this.stagedOutlines`
   - Iterates all line/arc elements in each outline to find min/max x/y

4. **Create `src/placement.ts`**
   - `PlacementBuilder` class with `by(gap?: number): number`
   - `below(comp)`, `above(comp)`, `rightOf(comp)`, `leftOf(comp)` — use `comp.bounds` for size-aware placement
   - `sameAs(comp)` — returns `{ x: number, y: number }` object
   - `workspace(pcb: PCB)` — reads outline bounds from `pcb.state`, returns `WorkspaceBounds`
   - Default gap constant: `DEFAULT_PLACEMENT_GAP = 2` (mm)

5. **Export from `src/index.ts`**
   - Export `below`, `above`, `rightOf`, `leftOf`, `sameAs`, `workspace`
   - Export `WorkspaceBounds`, `PlacementBuilder` types

6. **Add tests**
   - `tests/placement.test.ts` — unit tests for all placement functions
   - Tests with mocked components that have known positions and bounds
   - Tests for `workspace()` with known outline dimensions
   - Tests for default gap and custom gap
   - Tests for components without resolvable footprints (fallback behavior)

### 5. Design Decisions

- **Numbers, not proxies:** All placement functions return plain numbers, so they work seamlessly with the existing `pcb: { x: number, y: number }` interface. No new types in the `ComponentInit.pcb` field.
- **Lazy bounding box:** Footprint bounds are computed on first access and cached, so there's no upfront cost.
- **Outline-derived workspace:** The workspace bounds come from `pcb.outline()` calls, which is the natural way users define their board shape. If no outline is defined, `workspace()` returns bounds based on `(0, 0)` with zero dimensions and warns.
- **Graceful fallback:** If a component's footprint can't be resolved for bounding box, the placement functions use the anchor point only (equivalent to zero-size component).
