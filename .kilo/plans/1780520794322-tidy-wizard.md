# Plan: Modernize `@typecad/jlcpcb-parts`

## Context
`@typecad/jlcpcb-parts` is a standalone JLCPCB component search package. It currently builds and all 344 tests pass, but has several issues that need fixing to be a proper companion to the updated `@typecad/typecad`. The package is completely independent from typecad at the code level (no shared imports), but is referenced by typecad's CLI as an optional install.

## Changes

### 1. Fix package entry point (CRITICAL)
**Problem:** `package.json` points `"main": "dist/index.js"` and `"types": "dist/index.d.ts"` to the root `index.ts` output, which is the CLI runner that calls `runApplication(process.argv)` as a side effect. This means programmatic imports like `import { ComponentSearchEngine } from '@typecad/jlcpcb-parts'` trigger the CLI instead of importing the library.

**Fix in `@typecad/jlcpcb-parts/package.json`:**
```json
"main": "dist/src/index.js",
"types": "dist/src/index.d.ts",
```

### 2. Remove dead imports
- **`src/scoring/FuzzyScorer.ts`**: Remove `UnitConverter` import (line ~6, `import { ElectricalValue } from '../types/index.js'` can stay but `UnitConverter` is unused)
- **`src/data/DataManager.ts`**: Remove unused `join` from `path` import
- **`src/data/TimestampManager.ts`**: Remove unused `join` from `path` import
- **`src/data/CsvDownloader.ts`**: Remove unused `createWriteStream` from `fs` import

### 3. Align SearchResult type with typecad
**Problem:** typecad's `kicad-symbols` has `footprint?: string` and `fpFilters?: string[]` on `SearchResult` that jlcpcb-parts lacks.

**Fix in `src/types/index.ts`:** Add optional fields to `SearchResult`:
```typescript
export interface SearchResult {
  // ... existing fields ...
  footprint?: string;
  fpFilters?: string[];
}
```

This is backward-compatible (optional fields).

### 4. Convert error types from interfaces to classes
**Problem:** jlcpcb-parts defines errors as interfaces (`interface NetworkError extends Error`), which can't be used with `instanceof` at runtime. typecad's kicad-symbols uses proper classes extending a base error.

**Fix in `src/types/index.ts`:** Convert error types to classes:
```typescript
export class TypeCadError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'TypeCadError';
  }
}

export class NetworkError extends TypeCadError {
  code?: string;
  statusCode?: number;
  constructor(message: string, code?: string, statusCode?: number) {
    super(message);
    this.name = 'NetworkError';
    this.code = code;
    this.statusCode = statusCode;
  }
}

export class FileSystemError extends TypeCadError {
  code?: string;
  path?: string;
  constructor(message: string, code?: string, filePath?: string) {
    super(message);
    this.name = 'FileSystemError';
    this.code = code;
    this.path = filePath;
  }
}

export class ParsingError extends TypeCadError {
  line?: number;
  column?: number;
  constructor(message: string, line?: number, column?: number) {
    super(message);
    this.name = 'ParsingError';
    this.line = line;
    this.column = column;
  }
}
```

This enables `instanceof` checks in error handlers and aligns with typecad's pattern.

### 5. Update error creation sites
After converting error types to classes, update all places that create these errors to use `new`:
- `src/data/CsvDownloader.ts`: Change `throw { ... } as NetworkError` to `throw new NetworkError(...)`
- `src/data/CsvParser.ts`: Change `throw { ... } as ParsingError` to `throw new ParsingError(...)`
- Any test files that construct error objects

### 6. Update error handler to use instanceof
**`src/cli/ErrorHandler.ts`**: Update type guards to use `instanceof` instead of property checks:
```typescript
// Before: isNetworkError(error: unknown): error is NetworkError { return 'statusCode' in ... }
// After:  isNetworkError(error: unknown): error is NetworkError { return error instanceof NetworkError }
```

### 7. Update SearchEngine.ts formatResults to populate new fields
**`src/scoring/SearchEngine.ts`**: In `formatResults()`, attempt to extract footprint data from the JLCPCB `extra` JSON field. For JLCPCB parts, this data may not always have KiCad footprint references, so the fields will be optional/undefined for most parts.

### 8. Update tests
- Fix any tests that construct error objects as plain objects (change to `new NetworkError(...)` etc.)
- Verify all 344 existing tests still pass after changes
- The SearchResult changes are additive (optional fields), so most tests won't need changes

### 9. Version bump
Bump version from `1.0.3` to `1.1.0` (minor version for new fields and error class changes).
