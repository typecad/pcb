### Phase 2: Source Code Fixes (src/)

#### 2A. `src/types/index.ts` — Fix error class `instanceof`
- Add `Object.setPrototypeOf(this, new.target.prototype);` to each error class constructor (`TypeCadError`, `NetworkError`, `FileSystemError`, `ParsingError`)

#### 2B. `src/cli/CommandLineInterface.ts` — Multiple fixes
- **Remove unused `scoreColor`** in `displayDetailedResults` (line 546 — declared but unused since we removed Match Score)
- **Remove `getScoreColor` method** entirely if `scoreColor` is only used in compact/table display — actually, it IS still used in compact (line 568) and table (line 631). So keep the method, only remove the unused declaration in `displayDetailedResults`.
- **Fix `validateQuery()`** — replace the overly restrictive regex with one that allows common electronics Unicode chars (Ω, µ, ±, °, ℃, ω, etc.)
- **Fix `displayVersion()`** — read version from package.json via `import { createRequire } from 'module'` or just hardcode to match package.json version `1.1.0`
- **Fix `console.log` monkey-patching** — instead of replacing `console.log`, pass a `suppressOutput` flag or wrap the search call to check `format === 'json'` before logging

#### 2C. `src/scoring/SearchEngine.ts` — Fix broken timeout & remove double-counting
- **Fix broken timeout** — simplify `scoreComponentsWithTimeout`: remove the inner `Promise.race` wrapping a never-resolving promise. The method should be synchronous (since `rankComponents` is synchronous) with a `setTimeout`-based timeout that sets a flag checked in the loop, OR just make it a simple try/catch since the scoring is already synchronous.
  - Simplest fix: Remove the broken Promise.race/timeout wrapper entirely, make the method synchronous, and just keep a synchronous timeout check (using `performance.now()` between batches). The existing "timeout" was never functional anyway.
  - Alternative: Keep the async signature but make the inner promise actually check `performance.now()` between batches.
  - **Decision**: Replace with a simple synchronous approach that checks elapsed time between batch iterations, throwing a timeout error if exceeded.
- **Remove double-counting of cache hits/misses** — delete lines 158 and 164 (`this.cacheHits++` / `this.cacheMisses++`) since `getCachedResults()` already increments them.
- **Replace `console.log`/`console.error`** with Logger calls throughout.

#### 2D. `src/data/DataManager.ts` — Use Logger
- Replace all `console.log`/`console.warn` with `Logger.getInstance()` calls

#### 2E. `src/data/CsvParser.ts` — Use Logger
- Replace `console.warn` on line 53 with Logger

#### 2F. `src/app/index.ts` — Fix signal handler accumulation & process.exit
- **Signal handler accumulation** — guard against double-registration by checking a module-level flag
- **`process.exit(1)` in `Application.run()`** — throw the error instead, let the caller decide. The `runApplication` function already handles errors and calls `process.exit(1)`.

#### 2G. `src/cli/Logger.ts` — Add `resetInstance()` for testing & fix `any` types
- Add `public static resetInstance(): void` method
- Change `data?: any` to `data?: unknown` on `debug`, `info`, `warn` methods
- Fix internal `log` method to handle `unknown` type properly
