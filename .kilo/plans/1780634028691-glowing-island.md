# Plan: Contract System DX Improvements

Three changes to the contract system based on DX review feedback.

---

## Change 1: Accept Component directly in `ContractOptions`

Replace the string `mcuReference` field with a `mcu: Component` field. The contract function uses `mcu.reference` internally instead of searching by string. This eliminates the lookup/matching code entirely (addressing the silent failure concern — the component is the MCU, no matching needed).

### Files to change:

**`src/contract.ts`**
- `ContractOptions.mcuReference: string` → `mcu: Component` (import Component)
- Remove lines 132-144 (the `find` + `if (!mcu)` guard + `foundMcu` alias). Use `options.mcu` directly throughout.
- All references to `foundMcu` → `options.mcu`
- Update JSDoc on `ContractOptions`

**`src/pcb/pcb.ts`** (line 253)
- Update the type import in the `contract()` method signature to reflect the new `ContractOptions`

**`src/pcb/pcb_schematic_bridge.ts`** (line 23-29)
- `pcbContract` signature stays the same (accepts `ContractOptions`), but the options now contain a Component

**`tests/contract_extended.test.ts`**
- Update all `exportContract(pcb, { mcuReference: 'U1' })` calls to `exportContract(pcb, { mcu: mcu })`
- Remove the "should warn when no MCU is found" test (no longer applicable)
- Remove the "should handle MCU detection by reference without typehal" test (no lookup happening)
- Update remaining tests to pass Component directly

**`tests/contract.test.ts`**
- No changes needed (only checks module importability)

**`src/cli/typecad/skills/advanced.ts`** (line 13)
- Update example code from `mcuReference: 'U1'` to `mcu: mcu` (or similar)

**`docs/`** — Regenerated via typedoc, not edited manually

---

## Change 2: Flatten `typehal` from `ITypeHalInfo` to `Record<string, string>`

Remove the `ITypeHalInfo` wrapper interface. The `typehal` property becomes the pin lookup directly: `typehal?: Record<string, string>`.

### Files to change:

**`src/component.ts`**
- Remove `ITypeHalInfo` interface (lines 69-93)
- `ComponentInit.typehal?: ITypeHalInfo` → `typehal?: Record<string, string>` (line 116)
- `Component.typehal?: ITypeHalInfo` → `typehal?: Record<string, string>` (line 156)
- Update JSDoc on the property to reflect new shape
- Update the example in the JSDoc comment block to use flat structure: `typehal: { 'PB5': 'D13', ... }` instead of `typehal: { pinLookup: { 'PB5': 'D13' } }`

**`src/index.ts`** (line 2)
- Remove `ITypeHalInfo` from exports entirely (no deprecated alias)

**`src/contract.ts`**
- Line 34 JSDoc: `typehal.pinLookup` → `typehal`
- Line 204: `foundMcu.typehal?.pinLookup?.[pinName]` → `foundMcu.typehal?.[pinName]`
- Line 225: `if (foundMcu.typehal?.pinLookup)` → `if (foundMcu.typehal)`

**`tests/contract_extended.test.ts`**
- All `typehal: { pinLookup: { 'PB5': 'D13' } }` → `typehal: { 'PB5': 'D13' }` (lines 48-49, 138-139, 172-173)

---

## Change 3: Remove MCU matching/fallback code

This is handled as part of Change 1 — when the user passes the Component directly, there's no lookup to fail. The entire find-by-reference block (lines 132-144) and the "no MCU found" warning path are deleted.
